# Xlib: project notes for Claude

Personal portfolio styled as an Ubuntu desktop. Next.js 16 (pages router), React 19, Tailwind, deployed on
Vercel from `master` (Vercel root directory: `apps/web`). A **pnpm workspace**: pnpm only (`pnpm install`,
never `npm install`).

## Tests are mandatory

- **Every change ships with tests.** Logic goes in `lib/` (or a package's `src/`) with a Vitest unit test;
  UI behaviour gets a Playwright test in `apps/web/tests/e2e/`. Data scripts and the Apps Script backend have
  tests too.
- **Run `pnpm verify` (at the repo root) before every commit** and only commit when it passes. It runs each
  workspace package's `verify`; the site's runs lint, typecheck, unit tests, Python tests, a production build
  and the e2e suite. The `.githooks/pre-commit` hook enforces this (installed by `pnpm install`).
- Fix flaky tests rather than retrying them; e2e tests must not depend on outside services (mock them with
  `page.route`).

## Packages and boundaries

The restructuring plan is in `docs/restructure-plan.md`.

- `apps/web/` – the Next.js site.
- `packages/*` – self-contained apps (`@xlibraries/...`) that can later move to their own repos (as a git
  submodule or a published package). **A package may import only its own files, its declared dependencies,
  Node built-ins and `@xlibraries/app-sdk`** – never the site or another app package. The site imports
  packages only through their entry points. `apps/web/tests/unit/boundaries.test.ts` enforces this.
- `packages/app-sdk` – the contract: every app is a component taking `{ host }` (`openApp`, `addFolder`,
  `wallpaper`/`setWallpaper`, `track`, `volume` – the top bar's slider, `lib/sound-level.ts`). Apps get what they
  need from `host`, not by importing the shell.
- Packages ship TypeScript source (no build step); the site compiles them via `transpilePackages`.

## Commands (repo root)

| | |
| --- | --- |
| `pnpm dev` | the site's dev server (only one per folder in Next 16) |
| `pnpm lint` / `pnpm typecheck` / `pnpm test` | across every workspace package |
| `pnpm --filter @xlibraries/web test:python` | Python tests |
| `pnpm --filter @xlibraries/web exec next build --webpack && pnpm --filter @xlibraries/web test:e2e` | e2e tests |
| `pnpm verify` | everything |

## Site layout (`apps/web/`)

More detail in `docs/architecture.md` and `apps/web/scripts/README.md`; keep them current when you change how
things work.

- `apps.config.ts` – registers every app; `components/shell/` – desktop, windows, dock, top bar, boot and
  lock screens, driven by the `lib/window-manager.ts` reducer; `components/apps/*` – apps that live in the
  site; pure logic lives in `lib/`. Everything is typed function components; `@ts-nocheck` is a lint error.
- `content/` – what the site passes to packages (terminal folders and commands, browser bookmarks, Photo Drop
  settings).
- `pages/api/*` – five-line adapters over `@xlibraries/browser/server` (`checkFrame`, `readArticle`); `track.ts`
  (analytics beacons) and `admin/*` (login, logout, session, analytics).
- Admin mode: `/xlib` (`pages/xlib.tsx`) is the same desktop, locked until `ADMIN_PASSCODE`; sessions are signed
  cookies (`lib/admin-auth.ts`, 7 days); admin apps are `adminApps` in `apps.config.ts`. Analytics are our own
  (`@xlibraries/analytics`, Upstash Redis via `lib/kv.ts`; tests use `XLIB_MEMORY_STORE=1`). Plan:
  `docs/admin-plan.md`. Admin apps so far: Analytics, Photo Drop (status via `/api/admin/photo-drop`, which calls the
  script with `PHOTO_DROP_ADMIN_KEY`), Site Settings (hidden apps and banner in Redis via `lib/site-settings.ts`,
  public at `/api/settings`; Photo Drop open/closed is enforced by the script). Photo Drop settings: `content/photo-drop.json`.
- `public/privacy/`, `public/brave/newtab.html` – the site's own static pages. `public/drop/` and
  `public/vendor/` are generated by `scripts/vendor.mjs` (gitignored).
- `packages/engine` – the shared C++/sokol WebAssembly engine (`@xlibraries/engine`, a library package like
  `app-sdk`): the runtime (`xl.h`, audio worklet, text), vendored sokol/stb/HandmadeMath/doctest, the build
  pipeline (`scripts/build.mjs`) and test harness, physics (`xl_physics.h` over vendored Jolt v5.6.0, linked
  into modules with `physics: true`), and `EngineView` (the React canvas host). Apps that ship C++ modules depend
  on it; it imports no app.
- `packages/arcade` – the games, built on the engine for WebGPU and WebGL2 (`docs/arcade-plan.md`). Build with
  `pnpm --filter @xlibraries/arcade build:native` (needs `source ~/emsdk/emsdk_env.sh`, Emscripten 6.0.11);
  **commit `dist/`**, CI rebuilds it and fails on any difference. A full build stamps `dist/sources.sha256` over the
  Arcade's *and the engine's* sources and the arcade unit tests check it, so a change to either fails verify until
  **every** game is rebuilt. Games only react to keys while focused (`xl.h`).
  Turbo Trails (`docs/turbo-trails-plan.md`) uses vendored Box2D v3.1.1 behind `physics.h`; its rules, terrain and
  "feel" (face expressions, squash, shake) are graphics-free and tested natively (`tests/native/turbo_trails_test.cpp`);
  `art.h` draws, and the scene goes through a post-process shader. Its global leaderboard is
  `/api/arcade/leaderboard` (`lib/leaderboard.ts`, Redis sorted sets).
- Packages: `terminal` (Terminal + Calc), `browser` (Brave + server endpoints), `music` (+ the
  `xlib-music-snapshot` CLI), `photo-drop` (upload page + Apps Script backend, deployed with `pnpm deploy:photo-drop`, see its README).
- `.github/workflows/refresh-playlists.yml` refreshes the Music snapshot every Monday and commits it if tracks changed.
- `lib/security-headers.ts` – Content-Security-Policy and other headers (wired up in `next.config.ts`). Production
  allows no inline scripts, so production builds use webpack (Turbopack's build inlines a bootstrap script) and
  static pages in `public/` load their JS from files. A new script, font or frame source must be added there;
  every e2e test fails on a CSP violation.
- `scripts/vendor.mjs` – copies Leaflet, pdf.js and the India boundary data into `public/vendor/`, and the
  Photo Drop page plus its settings into `public/drop/` (runs on install, dev and build). Don't load libraries
  from CDNs.
- `scripts/` + `data/` – generators for `public/side-quests/*.json`; `data/music-playlists.json` feeds Music.
- Packages are linted by the root `eslint.config.mjs`; packages may use standard Tailwind utilities but never
  the site's theme tokens (`ub-*`), which the boundary test checks.
