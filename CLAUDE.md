# Xlib: project notes for Claude

Personal portfolio styled as an Ubuntu desktop. Next.js 16 (pages router), React 19, Tailwind, deployed on
Vercel from `master` (Vercel root directory: `apps/web`). A **pnpm workspace**: pnpm only (`pnpm install`,
never `npm install`).

## Tests are mandatory

- **Every change ships with tests.** Logic goes in `lib/` (or a package's `src/`) with a Vitest unit test;
  UI behaviour gets a Playwright test in `apps/web/tests/e2e/`. Data scripts and the Apps Script backend have
  tests too.
- **Run `pnpm verify` (at the repo root) before every commit** and only commit when it passes. It runs each
  workspace package's `verify`; the site's runs lint, typecheck, unit tests, Python tests, a production build
  and the e2e suite. The `.githooks/pre-commit` hook enforces this (installed by `pnpm install`).
- Fix flaky tests rather than retrying them; e2e tests must not depend on outside services (mock them with
  `page.route`).

## Packages and boundaries

The restructuring plan is in `docs/restructure-plan.md`.

- `apps/web/` – the Next.js site.
- `packages/*` – self-contained apps (`@xlibraries/...`) that can later move to their own repos (as a git
  submodule or a published package). **A package may import only its own files, its declared dependencies,
  Node built-ins and `@xlibraries/app-sdk`** – never the site or another app package. The site imports
  packages only through their entry points. `apps/web/tests/unit/boundaries.test.ts` enforces this.
- `packages/app-sdk` – the contract: every app is a component taking `{ host }` (`openApp`, `addFolder`,
  `wallpaper`/`setWallpaper`, `track`, `volume` – the top bar's slider, `lib/sound-level.ts`). Apps get what they
  need from `host`, not by importing the shell.
- Packages ship TypeScript source (no build step); the site compiles them via `transpilePackages`.

- The workspace is moving to independently versioned packages (`docs/streams-plan.md`, phase by phase).
  `pnpm graph` (`packages/graph`) checks every import and `#include` against `architecture/layers.json` (declared,
  public API only, downward layers, no cycles) and fails on anything not in `architecture/baseline.json`; fix a
  violation and run `pnpm graph --update` to drop it. Every package change carries a changeset (`pnpm changeset`;
  the four kinds of change are in `.changeset/README.md`). Track progress in `MIGRATION.md` (tick items, update the
  backlog count and the log as phases land). `@xlibraries` resolves to GitHub Packages (`.npmrc`; the token
  lives in `~/.npmrc`, CI's setup-node and Vercel's `NPM_RC`, never in the repo); `.github/workflows/release.yml` versions and publishes on every merge with changesets.

## Commands (repo root)

| | |
| --- | --- |
| `pnpm dev` | the site's dev server (only one per folder in Next 16) |
| `pnpm lint` / `pnpm typecheck` / `pnpm test` | across every workspace package |
| `pnpm --filter @xlibraries/web test:python` | Python tests |
| `pnpm --filter @xlibraries/web exec next build --webpack && pnpm --filter @xlibraries/web test:e2e` | e2e tests |
| `pnpm graph` / `pnpm graph --report` | the dependency-graph check / every violation with its files |
| `pnpm verify` | everything (the graph check first) |

## Site layout (`apps/web/`)

More detail in `docs/architecture.md` and `apps/web/scripts/README.md`; keep them current when you change how
things work.

- `apps.config.ts` – registers every app; `components/shell/` – desktop, windows, dock, top bar, boot and
  lock screens, driven by the `lib/window-manager.ts` reducer; `components/apps/*` – apps that live in the
  site; pure logic lives in `lib/`. Everything is typed function components; `@ts-nocheck` is a lint error.
- `content/` – what the site passes to packages (terminal folders and commands, browser bookmarks, Photo Drop
  settings).
- `pages/api/*` – five-line adapters over `@xlibraries/browser/server` (`checkFrame`, `readArticle`); `track.ts`
  (analytics beacons) and `admin/*` (login, logout, session, analytics).
- Admin mode: `/xlib` (`pages/xlib.tsx`) is the same desktop, locked until `ADMIN_PASSCODE`; sessions are signed
  cookies (`lib/admin-auth.ts`, 7 days); admin apps are `adminApps` in `apps.config.ts`. Analytics are our own
  (`@xlibraries/analytics`, Upstash Redis via `lib/kv.ts`; tests use `XLIB_MEMORY_STORE=1`). Plan:
  `docs/admin-plan.md`. Admin apps so far: Analytics, Photo Drop (status via `/api/admin/photo-drop`, which calls the
  script with `PHOTO_DROP_ADMIN_KEY`), Site Settings (hidden apps and banner in Redis via `lib/site-settings.ts`,
  public at `/api/settings`; Photo Drop open/closed is enforced by the script). Photo Drop settings: `content/photo-drop.json`.
- `public/privacy/`, `public/brave/newtab.html` – the site's own static pages. `public/drop/` and
  `public/vendor/` are generated by `scripts/vendor.mjs` (gitignored).
- `packages/engine` – the shared C++/sokol WebAssembly engine (`@xlibraries/engine`, a library package like
  `app-sdk`): the runtime (`xl.h`, audio worklet, text), vendored sokol/stb/HandmadeMath, physics (`xl_physics.h`
  over vendored Jolt v5.6.0, the `physics` feature), and `EngineView` (the React canvas host). It's a provider for
  the toolchain: `xlibraries.native` in its `package.json` says what it offers modules. It imports no app.
- `packages/tooling` – `@xlibraries/toolchain` (`xl-build`) builds the modules a package declares in `package.json`
  (`xlibraries.modules`: adapter, `uses`, sources, shaders, features, fonts, flags; `headless: true` for one build
  without graphics, for workers and Node) through adapter packages (`adapter-cpp-wasm`, which uses
  `adapter-shader-sokol`); `adapter-native-test` (`xl-native-test`) runs native tests with doctest. Each module's
  `dist/<module>/stamp.json` covers only what it's built from, so a change rebuilds (and fails the tests of) just
  the affected modules. `graph` is the dependency-graph check. The site serves modules at
  `/native/<package>@<version>/<module>/` (`scripts/vendor.mjs`, `lib/native.ts`).
- `packages/bot-lab` – the electronics and robotics simulator (`docs/bot-lab-plan.md`): a headless `sim/` (MNA circuit
  solver, parts, the Uno on avr8js, the Pi's header, the Pico on rp2040js with MicroPython, I²C devices on per-board buses, the
  bench loop), and machines in a physics world (a robot, an arm, a conveyor, a quadcopter): `native/world` (C++ on the engine's Jolt) is built headless into
  `dist/world/` and `native/view` (its 3D view, sokol) into `dist/view/`, by `pnpm --filter @xlibraries/bot-lab build:native` (needs Emscripten; **commit `dist/`**, CI rebuilds and
  diffs it; the unit tests check the stamps). The site gives it its folder (`createBotLab({ nativeBaseUrl })`). `firmware/` is vendored (MicroPython, and an RP2040 boot ROM with its float library zeroed for licensing:
  `pico-rom-float.ts` replaces it; see `firmware/README.md`), copied to `public/vendor/pico/` by `scripts/vendor.mjs`) under a React bench. The bench runs in a worker
  (`runtime/`); the Raspberry Pi runs Python on Pyodide (vendored to `public/vendor/pyodide/`) with `python/`
  (`gpiozero`, `RPi.GPIO`, `pigpio`, `smbus2`, simulated `time`) bundled by `pnpm sync:python` (the unit tests check it's current).
  `time.sleep` steps the bench and, with JSPI, suspends Python so messages arrive mid-sleep; the unit tests need
  Node 24's `--experimental-wasm-jspi` (set in its vitest config). Templates ship their sketches with compiled hexes (`templates/`, bundled into
  `src/templates/generated.ts` by `pnpm sync:templates`; the unit tests check it's current). `services/arduino-compiler/` (a workspace package for its Python tests) is the `arduino-cli` image: it
  compiles the templates (`pnpm compile:templates`, needs Docker; CI recompiles and fails on drift,
  `.github/workflows/bot-lab-templates.yml`) and builds visitors' sketches, one GitHub Actions run per build (`.github/workflows/bot-lab-compile.yml`, the
  image on GHCR via `arduino-compiler.yml`, set up once with `setup-actions.sh`). The site's `/api/bot-lab/compile` and
  `/api/bot-lab/compile-job` (`lib/bot-lab-compile.ts`) start runs with `BOT_LAB_GITHUB_TOKEN` and swap the sketch and
  result with them using `BOT_LAB_JOB_SECRET`. Locally, `BOT_LAB_COMPILER_URL` + `BOT_LAB_COMPILER_SECRET` use the
  image's HTTP mode. Rate-limited and cached by sketch; e2e tests mock the endpoint.
- `packages/arcade` – the games, built on the engine for WebGPU and WebGL2 (`docs/arcade-plan.md`). Build with
  `pnpm --filter @xlibraries/arcade build:native` (needs `source ~/emsdk/emsdk_env.sh`, Emscripten 6.0.11);
  **commit `dist/`**, CI rebuilds it (`--force`) and fails on any difference. `build:native` rebuilds only the games
  whose stamps are stale (`build:native <id>` for one); the unit tests check every stamp. Games only react to keys
  while focused (`xl.h`).
  Turbo Trails (`docs/turbo-trails-plan.md`) uses vendored Box2D v3.1.1 behind `physics.h`; its rules, terrain and
  "feel" (face expressions, squash, shake) are graphics-free and tested natively (`tests/native/turbo_trails_test.cpp`);
  `art.h` draws, and the scene goes through a post-process shader. Its global leaderboard is
  `/api/arcade/leaderboard` (`lib/leaderboard.ts`, Redis sorted sets).
  JyotiRath (`docs/jyotirath-plan.md`) is the same design told as a story in 3D. Chapter I, Mohenjo-Daro, alternates
  short drives (`drive.cpp`: reach, chase, clock, deliver, storm, lamps) with Hitman GO-style boards in the districts
  (`go.cpp` rules and solver, `boards.cpp`, ending with the Bronze Thief's board); `chapter.cpp` carries the bag of tools
  between them and lets how a board was solved pick the next drive; districts are ruins (`models.cpp` ruinify) until
  their board is cleared. Between beats `main.cpp` plays scenes (the chariot rolls itself, a local talks, a wave of light
  raises the board; the camera blends between modes); `hints.cpp` teaches each board rule once, when it's useful. Every model is made in
  code (`mesh.h`); shadows, MSAA and a tilt-shift post pass in `shaders/jyotirath.glsl`. All but `main.cpp` is
  graphics-free and tested natively.
- Packages: `terminal` (Terminal + Calc), `browser` (Brave + server endpoints), `music` (+ the
  `xlib-music-snapshot` CLI), `photo-drop` (upload page + Apps Script backend, deployed with `pnpm deploy:photo-drop`, see its README).
- `.github/workflows/refresh-playlists.yml` refreshes the Music snapshot every Monday and commits it if tracks changed.
- `lib/security-headers.ts` – Content-Security-Policy and other headers (wired up in `next.config.ts`). Production
  allows no inline scripts, so production builds use webpack (Turbopack's build inlines a bootstrap script) and
  static pages in `public/` load their JS from files. A new script, font or frame source must be added there;
  every e2e test fails on a CSP violation.
- `scripts/vendor.mjs` – copies Leaflet, pdf.js and the India boundary data into `public/vendor/`, and the
  Photo Drop page plus its settings into `public/drop/` (runs on install, dev and build). Don't load libraries
  from CDNs.
- `scripts/` + `data/` – generators for `public/side-quests/*.json`; `data/music-playlists.json` feeds Music.
- Packages are linted by the root `eslint.config.mjs`; packages may use standard Tailwind utilities but never
  the site's theme tokens (`ub-*`), which the boundary test checks.
